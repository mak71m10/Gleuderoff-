## Замер (Сигрестад, `buildCity`, headless Chrome + swiftshader, 915×412 «телефон»)
Стенд: CDP-скрипт вне репозитория; метки по стадиям внутри `buildCity`, потом убраны.

| Стадия | До, мс | После, мс |
|---|---|---|
| Маски + сетка высот | 337 | 76 (маски 2, сетка высот 73) |
| Улицы (`buildStreets` + `roadAt`) | 437 | 173 |
| Сетка занятости | — | 83 |
| Холст земли / материалы | 265 | 266 |
| Вода (цикл сетки + меш) | 140 + 114 | 40 + 75 |
| **`buildCity` всего** | **~1430** | **~800** |
| Первый кадр | 1031 | 450 |

ПК-вид (1280×720, до правок): `buildCity` ≈ 1011 мс, первый кадр ≈ 909 мс. Правки касаются общего кода улиц, вид не менялся.

Важно: в swiftshader реальные «80 с» на слабых телефонах не воспроизводятся; замер показывает относительное сокращение работы. Разброс между прогонами заметный (часть выигрыша — шум, первый прогон шёл с холодным кешем vite).

## Что сделано
- `city3dStreets.ts`: убраны аллокации в горячих циклах — `off.some(...)` с замыканием заменён на индексный цикл; `for…of` с деструктуризацией по `NB` заменён на плоские массивы `NBX/NBY/NBL` и индексный цикл; `dist[q]` читается один раз на ячейку.
- Вид домов, палитры, жители — не менялись.

## Что осталось (идеи, не сделано)
- Холст земли на телефоне (265 мс): меньше эллипсов/крапа и `texMax` — это меняет вид, нужно решение автора.
- Прогрев шейдеров (`renderer.compile`) до первого кадра; первый кадр ≈ 450 мс.
- Порционная сборка с уступкой потоку между стадиями (UI не замирает).
- Телефон: LOD/pixelRatio/тени уже различаются по `mobile` (pixelRatio ≤ 1.5, без antialias, тень отключена при N>500, карта теней 1024); дополнительных урезаний не вводил, чтобы не ухудшить вид.

## Проверки
- `npx tsc --noEmit` — без ошибок.
- Сборка APK: `npm run build:web && npm run android` (результат — в отчёте сессии).

## Задача 2 — карта на ноутбуке бета-тестера (i5-12450H + RTX 3050, 15 FPS в покое)

Сделано (не закоммичено, ждёт решения автора):
- `src/main/index.ts`: `app.commandLine.appendSwitch('force_high_performance_gpu')` до `app.ready` — на гибридных ноутбуках Electron берёт дискретную RTX, а не встроенную Intel. После старта в консоль пишется `[gpu] <рендерер> <vendor:device (активна)>` (`app.getGPUInfo('basic')`) — по этой строке видно, какая карта работает. Просить тестера прислать её.
- `MapView.tsx` (эффект областей): для каждого полигона запоминается ключ стиля (`sk`), `setStyle` вызывается только при реальном изменении. Раньше при каждом зуме/наведении (`zoom`, `hoverTick` в зависимостях) перекрашивались ВСЕ полигоны, а каждый `setStyle` заказывает у холста полную перерисовку — отсюда микрофризы при смене масштаба. Поиск государства для подсказки — через `Map`, а не `states.find` на каждый участок.

15 FPS в покое — разбор по коду: вечного цикла анимации на карте нет (`ProvinceRenderer._draw` — по требованию). Подозреваемые: (1) встроенная Intel-графика вместо RTX (лечится переключателем выше); (2) CSS-фильтр на `.map-base` (styles.css ~178) заставляет композитор пересчитывать большой слой при каждом сдвиге — убирать = менять вид, решает автор; (3) перерисовки React от тиков хранилища/наведения. Реальный GPU-замер в headless/swiftshader невозможен — подтвердить нужно на машине тестера.

Прогрев первых запусков провинций/областей: `loadRaster` декодирует 4096×2336 png в `Uint16Array` через `getImageData` (~9,5 млн пикселей) в основном потоке — разовое замирание 100–200 мс. Не менял (риск без замера); идея — предзагрузка растра при старте или `createImageBitmap` + воркер.

Идея «карта одним bmp, как провинции в HOI4»: для провинций УЖЕ так (`resources/default-world/maps/provinces.png`, 4096×2336, 460 КБ, id-растр). Для подложки карты смысла нет: тайлы ≈ 71 МБ, один растр потребовал бы LOD/стриминга — это и есть тайлы. Не делаю.

Проверка: `npx tsc --noEmit` — без ошибок.
